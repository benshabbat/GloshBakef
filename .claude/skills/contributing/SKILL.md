# Landing a change

## Branch, never `main`

`<kind>/<kebab-summary>`, where kind is `feature`, `fix` or `docs`. Real ones from this
history: `feature/video-frame-filtering`, `fix/audit-hardening`, `docs/readme-first-run`.
Work goes to a branch, then a PR, then a merge commit — every commit on `main` past the
first arrived that way.

## The gate

```
npm run check     # check.mjs (manifest paths, page assets, syntax) + test.mjs
npm run build     # if anything under src/content, src/offscreen or src/shared changed
```

`npm run check` is the single pre-commit gate. `src/shared/` is the one that catches people
out: it is compiled into both bundles **and** loaded raw by the worker and the UI, so an
edit there without a rebuild leaves the two halves of the extension disagreeing. See
`build-extension`.

A change to pure logic in `src/shared/` comes with assertions in `scripts/test.mjs`. That
layer is where a subtle mistake silently hides innocent images, and it is the only layer
with automated coverage at all.

## Never committed

- `dist/` — gitignored, generated. A commit that adds it is wrong.
- `node_modules/`, `.env*`, editor droppings — see `.gitignore`.
- `icons/*.png` **are** tracked, despite being generated by `make-icons.mjs`.

## Commit messages

Read `git log` before writing one; the voice is consistent and worth matching.

**Subject** — an imperative sentence saying what the change does to the product, capital
first letter, no trailing period, no `feat:`/`fix:` prefix, no scope in brackets:

```
Refuse to fetch URLs the page could not have fetched itself
Filter videos by their frames, not just their poster
Stop working on pages the filter was told to leave alone
Sanitize stored settings entry by entry, not just by type
```

Not `Add isFetchableUrl()` — that names the diff, which the diff already does. Name the
behaviour that changed.

**Body** — what was wrong, the mechanism, and the consequence the user or the next
maintainer would have hit. Wrapped at ~76 columns. The mechanism is the part that earns the
paragraph:

> `migrate()` checked that keywords and allowlist were arrays and trusted their contents.
> Storage is synced across profiles and written by whichever version of the extension got
> there first, so that is not enough: one unusable hostname makes `toMatchPattern` emit
> `*:///*`, Chrome rejects the whole `registerContentScripts` call over it, and "hide until
> checked" silently stops working everywhere.

A commit that does several things groups them under a lead line — "Three things the content
script kept paying for after it had no reason to:" — with one bullet per thing, each
carrying its own mechanism. Secondary changes that live in the same paths get their own
short section rather than being smuggled in silently.

When the suite grows, say so: `Tests: 63 -> 89 assertions, covering the URL gate and the
sanitizing.`

**Trailer** — every commit here ends with:

```
Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>
```

## PRs

Title = the subject line. Body = the commit body, or a summary of it when the branch has
several commits, plus what was verified in a browser and what was not — most of this
extension has no automated coverage, so "tested" for a path nobody opened Chrome for is a
false report. Merge with a merge commit (`gh pr merge --merge`), matching the history.

End PR bodies with:

```
🤖 Generated with [Claude Code](https://claude.com/claude-code)
```

## Docs are part of the change

This repo treats documentation drift as a defect, and has a commit whose entire purpose was
closing it. When behaviour changes, check in the same breath:

- **README.md** — Hebrew, user-facing. The settings table, the limits section
  (`מגבלות`) and the privacy section (`פרטיות`) all make claims that a code change can
  falsify.
- **`.claude/skills/`** — the skill that describes the thing you changed. A skill that
  documents a mechanism that no longer exists is worse than no skill.
- **`.claude/agents/`** — an agent's brief encodes architecture. New context boundary, new
  invariant, moved file: the briefs that name it need updating.
- **manifest.json / package.json version** — only for a release; see `release`.

## Before calling it done

1. `npm run check` passes.
2. `npm run build` if the bundles are affected, and the extension reloaded in Chrome.
3. The paths you actually walked in a browser, named — and the ones you did not, also
   named.
4. Docs above, reviewed.
5. `git status` clean of `dist/`.
